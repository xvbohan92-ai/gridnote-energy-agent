# v0.2：任务约束、语义核验与评测口径

## 改进的目标与边界

这轮新增的能力是：在有限、明确的能源分析任务中，发现“SQL 合法且可以执行，但业务数值不正确”的错误，并给规划器具体反馈。它不是一个能够证明任意自然语言问题和任意 SQL 等价的系统，也未证明真实模型或真实 PJM 数据上的性能提升。

规则解析器提取任务种类、时间粒度、阿拉伯数字 Top-K 和工作日/周末参数。支持趋势、小时峰值、预测误差、观测电量、记录数和异常筛查。明显未支持的中位数、相关性、增长率、因果问题等转为 custom；规则模式拒绝 custom，模型模式允许生成查询但标注语义未覆盖。有限规则仍可能误解复杂表述，应通过真实问题集继续检验。

## 三组对照

| 流程 | 只读及时间范围 | 预编译/执行错误纠正 | Python 指标核验与语义反馈 |
| --- | --- | --- | --- |
| baseline | 有 | 无，单次生成 | 无 |
| agent | 有 | 有，最多 2 次重写 | 无 |
| domain（默认） | 有 | 有，最多 2 次重写 | 有，和语法错误共用重试上限 |

三组使用相同的规划器、结构化任务参数、查询边界、结果展示上限以及本地历史异常工具。这个设置用于隔离领域数值核验的影响，并不代表完全没有领域信息的通用模型基线。

## 运行时领域数值核验

`metrics.py` 直接读取参数化、受区域和日期限制的原始数据，用 Python 独立计算任务定义，不调用生成的 SQL 或 SQL 编译器的计算逻辑。它检查必需列（空结果也检查）、行数、排序、Top-K、数值、NULL 与指标分母。必需列名来自任务编译合同，数据值独立重算；可选 RMSE 列也会核验。其他额外列不被视为已验证。已验证任务的标题、图表字段和方法说明采用可信任务定义，防止模型用未经核验的额外列绘图。

失败返回 `semantic_error` 和具体字段/规则提示，再让规划器重写；不发送原始数据行或参考数值给模型。两次重试后仍失败则返回错误，清空不可信数据与图表。模型显式 LIMIT 500 时，如果完整参考结果超过 500 行，会依据独立计数补上截断标记。

独立重算需要额外扫描数据；当前单区域、366 天、小时粒度的范围有限。它不适合直接扩展到任意规模仓库，后续需要按指标设计聚合验证与采样策略。SQL 的 VM 预算只约束模型 SQL；本地历史工具和 Python 验证不是同一个 SQL 沙箱。

## 指标与覆盖

- 趋势：实际/预测负荷分别按各自非空小时平均，单位 MW；返回实际与预测覆盖数。按周时周一为 UTC 周起点。
- MAE/MSE：仅使用预测非空小时，分别计算平均绝对/平方误差。RMSE 为 MSE 开平方；MSE 的三位小数舍入可能造成 RMSE 末位差异。
- MAPE：仅使用预测非空且实际负荷大于零的小时；返回 `mape_hours`，与 MAE 分母分开。
- 电量：每行是完整 1 小时平均功率，`Σ(load_mw × 1h)` 单位 MWh；缺失小时不补零。
- Top-K：原始小时按负荷降序、UTC 时间升序稳定排序；K 为 1–100。尚不支持日峰值排名。
- 工作日/周末：UTC 周一至周五 / 周六周日，不包含节假日日历。
- 覆盖：按用户请求窗口及日类型过滤计算应有小时数、实际小时数、缺失小时、预测可用小时、MAPE 有效小时。部分起止日会显式缺小时，不因数据集自身无内部空洞而伪称完整。

## 历史异常筛查

对时点 t，仅取 `[t-28天, t)` 中相同 UTC 小时和相同工作日/周末类型的观测。至少需要 4 点；不足时不评分，也不当作正常。

基线为历史中位数 m，MAD 为 `median(abs(x-m))`。工程筛查分数为：

```text
scale = max(1.4826 * MAD, abs(m) * 0.01, 1 MW)
robust_z = (actual - m) / scale
flag if abs(robust_z) >= 3.5
```

MAD 分数的参考来自 [NIST 对 modified Z-score 的说明](https://www.itl.nist.gov/div898/handbook/eda/section3/eda35h.htm)。本项目的滚动同类分组、最小样本数与尺度下限是额外工程选择，未在真实电力数据上调优；不是正式显著性检验、故障判断或因果分析。

工具会额外读取请求起点前最多 28 天作为历史，但输出仅包含请求窗口内的异常。每点不读取当前点和未来点。返回实际历史读取区间、已评分小时数、历史不足小时数、全部标记数与展示数，SQL 和绑定参数可检查。零个标记仅意味着已评分点未达到该阈值；零个可评分点返回 insufficient_data。

## 合成评测 v2

`energy-contract-v2` 使用固定种子 42、2025-01-01 至 2025-01-28 的 2,016 条合成小时记录，三个独立区域各 672 条。另在隔离数据库中构造缺失小时、空预测、实际值为零三个变体。不会读取或改写用户导入的数据库。

26 题覆盖中文/英文、Top 5/10/100、小时/日/周/整体、工作日与周末、记录数、电量、缺失值、零值、历史不足，以及越界日期、写操作和数据缺失等拒绝。`evaluation.py` 独立计算参考答案，不调用运行时任务解析器、编译器、指标核验器或异常检测函数；异常参考使用直接扫描过去数据的方法计算，而非复用运行时队列算法。

评分要求预期 outcome、必需列数值和稳定行序一致。数值采用 0.011 绝对容差和 1e-9 相对容差；NaN/Inf 不能通过。额外列不参与参考评分。当前规则模式三组均为 26/26，说明这些有限任务可用，不能证明泛化或模型改进。

另列四类显式注入、能够执行的错误 SQL：

| 故障 | 注入变化 | baseline | agent | domain |
| --- | --- | --- | --- | --- |
| 功率聚合错误 | 平均负荷 AVG 改成 SUM | 错误未被发现 | 错误未被发现 | 发现并反馈后恢复 |
| 电量聚合错误 | 电量 SUM 改成 AVG | 错误未被发现 | 错误未被发现 | 发现并反馈后恢复 |

诊断规划器只在收到 semantic_error 后返回正确 SQL。这是可复现的工程故障注入：domain 4/4、另外两组 0/4，不能当作真实 LLM 自我纠错率、真实模型准确率提升或研究创新证明。单独测试还覆盖始终错误达到上限、错误结果不展示、请求范围、无未来泄漏以及周末历史匹配。

## 失败分类与报告

`outcome` 分为 success、empty、insufficient_data、refused、rejected、failed。拒答必须匹配预期的 outcome 与 error_code；provider_error、configuration_error、query_error、semantic_error 等不能算成正确拒答。未知模型拒答也不会自动等价于数据缺失拒答。

报告分别列出总体正确率、可回答题正确率、类型化拒答正确率、系统失败数、P50/P95 延迟、逻辑模型调用数、tokens 与可选成本。模型配置失败会记录并继续评测，而不是用错误充当通过。token 消耗在请求失败时可能未知，成本估计也不包含缓存优惠或其他收费。

## 尚未完成的真实验证

真实 PJM 管道、独立业务测试集、真实模型调用、预测发布时间/版本/提前量对齐、节假日日历都尚未完成。下一阶段需要接入用户授权的数据与模型，在独立问题上重复运行三组实验，人工复核语义映射和答案，报告真实正确率、拒答行为、延迟及成本；异常阈值也需要标注数据支持。

## 绘图复核暴露的失败样例

`energy-agent visualize` 从固定 seed=42 的合成数据中单独取 PJM_RTO 标识的 2025-01-22 至 2025-01-28 共 168 个小时，检查 `create_demo` 明确注入的 2025-01-22 17:00、18:00、19:00 三个小时。

当前检测器未标记这 3 个已知注入小时，而标记了另外 5 个小时。已将逐小时实际值、合成预测、已知事件及检测标记一起导出至 `docs/figures/energy-example.csv`，并在业务样例图中明确展示。这不能用来声称异常检测已有效，也不应该因为 26 题参考计算结果吻合而忽略。

参考答案复算验证的是实现是否符合指定算法，注入事件复核验证的是算法能否找到这个受控样例中的目标，两者不同。未来应在独立开发/测试事件集合中验证异常分数、非平稳基线和阈值；不能只围绕这 3 个时点调整阈值后声称泛化提升。

工程概览图中的 P50/P95 来自同一份报告的 26 个混合任务、单次本地规则运行。它不包含真实 LLM 网络耗时，也不提供统计置信区间或线上服务承诺。主动注入的语义错误恢复仍属于脚本化工程诊断。
